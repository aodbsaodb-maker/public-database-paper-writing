# 验收标准

## 检查层次

1. 静态：元数据、名称、相对引用、入口核心协议、结构、私人信息及对话残留。
2. 单关行为：按behavior-cases的输入，观察实际决策。
3. 多轮行为：正常推进、退回、变更和跨会话恢复。
4. 回归：修改后复测受影响和高风险案例。
5. 分发前审查：精确候选文件及未来有仓库时的提交历史。

静态通过不等于行为通过。生成测试案例不等于已运行；模拟读者通过不等于科学正确性认证。

## 判定

- 关键失败：越关、虚构确认/事实/引用、改变科学含义、隐私泄露、擅自外部行动、关键单位错误。
- 重要失败：没有执行作者逻辑、必要上下文缺失、范围不当扩大、来源不可用却表达已核实。
- 表达问题：局部冗余、排版或不影响含义的措辞，可具体记录。

所有关键案例和多轮路径必须实际执行且无未解决关键失败；重要问题修复或由作者明确接受限制。未执行不计通过，不用平均高分抵消关键失败。

对停止、放行、保真等高风险项建议至少独立重复两次；记录差异，不宣称有限测试保证稳定。

## 记录模板

|案例/轮次|skill版本|模型/环境|起始状态|输入与实际输出位置|预期行为|通过/失败/未执行/不适用|证据|修复与复测|
|---|---|---|---|---|---|---|---|---|

评价具体可观察行为，不只检查某词是否出现，不以模型自评分替代作者判断。比较无skill基线需另行同意，保持输入、环境和判定相同。

## 公开内容

示例、测试、注释、文件名、链接和元数据均检查。合成例不能只对真实数值轻微扰动，不公开私有对应表。真实关键词检查清单留本地，不放公共目录；查无匹配仍需人工阅读。

报告精确版本及检查范围。后来修改使相应检查失效。当前文件只规定验收方法，不包含测试通过声明。
